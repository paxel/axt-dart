# 2. AXT 0.2.0: types as descriptions, relations resolved by the library, typed classes from avro

Date: 2026-11-22

## Status

Accepted. Replaces the "schema text" of a type in [ADR 1](0001-the-public-api.md) (Q9) with its description; the rest of ADR 1 stands.

## Context

AXT 0.2.0 (released 2026-11-22) describes every type as a description of bricks (`axt.Field`, `spec/fields.md`), from which its Avro schema is derived; offers and the header of a file carry descriptions instead of schema texts. It adds relations between records, also of other senders, extensions of other apps' fields, share options for links, and proposals of single relations and extension fields. `bricks` is a new category that every library must pass; the schema attributes and `metadata` are retired. `axt_protocol` 0.1.0, run against the 0.2.0 suite, passes 747 of 906 vectors. The `avro` package has had code generation since 0.2.0 and the generator as a library since 0.3.0. Grilled on 2026-11-22 (Q17 to Q21).

## Decision

- **AXT 0.2.0 only** (Q17): `axt_protocol` 0.2.0 speaks AXT 0.2.0; 0.1.0 offers and files are no longer read.
- **Types are descriptions** (Q18): an app gives a type as its description in the JSON form of `spec/fields.md`, section 10.3. The library validates it, derives the schema and its fingerprint, and answers `DESCRIPTION_INVALID` for one that is not valid. Typed builders of the bricks may follow as a minor version.
- **The library resolves relations** (Q19): it keeps a relation index in the store and offers `resolve(target)` and `linkedFrom(sender, id)`, following device-set joins and removed keys.
- **Links per record** (Q20): `OutgoingRecord.withLinks` says whether a record's links go along to a receiver of another user; without it the library keeps only relations to records shared in the same call and empties the extension lists (`spec/shares.md`, section 19.1). A receiver marked as an app of the own user gets every record whole.
- **Typed classes from avro** (Q21): `dart run axt_protocol:generate <description.json>` derives the schema and generates the classes with `generateDart` of `package:avro/generate.dart`, with a `TypedCodec`. The eight example types of AXT 0.2.0 ship generated in `package:axt_protocol/examples.dart`.

## Considered options

- Speaking both 0.1.0 and 0.2.0: two offer bodies and two file headers, two suites in CI, for a 0.1.0 that no app used.
- Typed brick classes only, or a generator of its own: a large public API, or a second generator beside avro's.
- Relations resolved by each app: the rules of device sets would be in every app.
- Links for a whole file, or stripped by the app: a receiver with two shares could not be served in one file, or every app would implement section 19.1.

## Consequences

- `avro` goes from `^0.1.1` to `^0.3.0`.
- The CI pins `axt-0.2.0.tar.gz`, and the vendored `test/vectors/shares.json` is that of 0.2.0.
- An app moving from 0.1.0 changes its `OutgoingRecord` schemas and its reader schemas to descriptions.
